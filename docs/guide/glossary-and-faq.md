# 术语表与常见问题

## 术语表

| 术语 | 英文 / 写法 | 解释 |
| --- | --- | --- |
| 预设 | preset | 决定模型以什么身份、按什么要求写作的一组提示词和设定 |
| 产物 | artifact，`*.apreset.json` | 构建后得到的预设文件，用户安装的就是它 |
| 清单 | manifest，`preset.yaml` | 预设的总设定文件；除元数据外可拆到 `manifest/*.yaml` |
| 区域 | region | 请求中的一段固定位置，模组的内容放在区域里 |
| 原生区域 | native region | 由 ST 填入内容（角色卡、世界书等）的区域 |
| 模组 | module | 一个 Markdown 文件，代表一个功能或一组规则 |
| 条目 | entry | 模组放进某个区域的一段内容；一个模组可以有多个条目 |
| 分组 | group | 面板上模组或参数的分类 |
| 单选集合 | exclusive | 同时只能有一个生效的一组模组 |
| 参数 | param | 写作页上的输入项，如语言、长度 |
| 条件 | `when` / `@if` | 决定内容是否出现的判断式 |
| 指令 | directive，`<!-- @… -->` | 写在 HTML 注释里、给 AP 看的标记，如 `@entry`、`@if` |
| 注释 | comment，`<!--# … -->` | 只给作者看的说明，编译时移除、不发送给模型，可跨行 |
| 模板 | template，`<!-- @template -->` | 每次生成时运行的 EJS 模板（JavaScript），输出成为提示词；安装时需用户确认信任 |
| 宏 | macro，`{{ap::…}}` | 生成时被替换成实际内容的占位符 |
| 角色 | actor | 参与写作的身份，如叙述者、编辑、用户 |
| 前缀 | prefix | 对话式下标识“谁在说话”的开头，如 `Freesia: ` |
| 工作流 | workflow | 每轮回复要经过的阶段序列 |
| 阶段 | stage | 工作流中的一步：文本、正文或修改 |
| 故事工作流 / 任务工作流 | story / task workflow | 推进故事用的 / 处理元指令、代写、总结、脚本调用用的 |
| 传输方式 | transport | 模型交回输出的形式：预填充、纯文本、结构化、工具、多工具 |
| 写法 | style：dialogue / imperative | 对话式（预填充、纯文本）/ 指令式（其余三种） |
| 结构 | structure | 正文之外的附加输出：回复、记忆、总结、代写、事件摘要、选项、自定义 |
| 元指令 | meta-instruction，`@叙述者` | 用户直接对叙述者说的话；分为纯元指令与混合元指令 |
| 记忆 | memory | 标题 → 内容的条目，分聊天记忆与全局记忆 |
| 总结 | recap | 完整的剧情概要，替代它覆盖的聊天记录 |
| 事件摘要 | synopsis | 每段故事的时间、地点、事件、概要 |
| 节省 Token | token saving | 用事件摘要替代较早的回复、截断较早的长用户消息 |
| 构建变量 | build variable，`vars` | 由多个模组共同填写、在一处读出的值 |
| 插入点 | insertion point | 预设开放给用户放入“我的模组”的位置 |
| 用户模组模板 | user module template | 预设附带的示例用户模组（`user-module-templates/`），新建“我的模组”时可以从它开始 |
| 随预设安装的用户模组 | bundled user module | 写在预设 `user-modules/` 中、安装预设时放进“我的模组”的用户模组；之后归用户所有 |
| 我的模组 | user module | 用户在面板上写的模组 |
| 推荐配置 | recommended configuration | 预设提供的一套设定，如“Gemini” |
| 示范轮次 | synthetic turn | 工具模式下放在请求末尾的一轮虚拟工具调用，示范工具用法 |
| Carrier | carrier | AP 为每个预设生成的 ST 预设（`AP · <预设名>`），负责放置原生内容与区域 |
| 迁移 | migration | 改名后告诉 AP 旧 id 对应哪个新 id |
| Agent Skills | `.agents/skills` | 写给 AI Agent 的说明书，教它设计、编写、测试 AP 预设 |

## 常见问题

**我不会编程，能做预设吗？**

能。预设的主体是提示词（普通文字）和少量设定。推荐用 AI Agent 处理格式和检查（见[第 2 章](02-build-with-ai-agent.md)），你专注于内容。

**我已经有一个 ST 预设，怎样迁移到 AP？**

把原来的每个提示词条目看作一个模组的候选：总是开着的放进始终生效的模组，可开关的做成开关，互斥的做成单选；原来的“思维链”提示改写成工作流阶段；原来用正则提取的选项、状态栏改成结构。可以把原预设的 JSON 交给 Agent，让它按 ap-preset-design 技能先整理出设计稿。花瓣 v7 就是从 v6 的 ST 预设这样迁移过来的。

**一定要写两种写法（对话式 / 指令式）吗？**

不一定。如果你只打算支持某一类传输方式，只写一种即可，在推荐配置里只提供对应的传输方式。但关键的几处（身份、结尾提醒、工作流各阶段）为两类分别写，效果通常更好。

**提示词用中文还是英文写？**

都可以。英文通常更省 Token，多数模型对英文指令的遵循也更稳定；用户可以通过语言参数让模型用中文写作。面板显示的名称可以通过界面翻译提供中文。

**用户能看到我的提示词吗？**

能。预设文件是公开的 JSON，用户也能在调试页看到组装结果。AP 预设不提供加密或隐藏。

**为什么我的修改没有生效？**

依次检查：`npm run dev` 是否还在运行、有没有构建错误；调试页的开发源是否“在线”；ST 是否选中了 `AP · <预设名>`；模组是否开启、条件是否满足（看“最近组装”）。

**用户的设置会因为我更新预设而丢失吗？**

不会，只要你没有改动 id。用户的配置修改、我的模组、记忆都独立保存。必须改 id 时请写迁移（见[第 12 章](12-test-and-release.md#改名与迁移)）。

**想要的功能 AP 没有怎么办？**

先看能不能用现有的积木组合出来：条件、构建变量、自定义结构能覆盖很多需求。确实做不到，欢迎到 [advanced-preset](https://github.com/mirrorange/advanced-preset/issues) 提出建议。
