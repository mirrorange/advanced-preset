# 12. 测试、发布与更新

## 发布前的检查清单

1. **`npm run check` 没有错误**。警告也逐条看一遍：它们常常指向笔误（比如一个从未被读取的变量、一个没有分组的模组）。想更严格，用 `npx ap check --strict`，警告也算失败；
2. **每种推荐配置都实际试过**：在 ST 里切换到每一套推荐配置，至少完成：
   - 普通的几轮对话；
   - 重新生成、滑动（swipe）、继续；
   - 纯元指令（`@叙述者 你好`）、混合元指令；
   - 代写按钮、总结（如果支持）；
   - 打开“节省 Token”后的长对话（如果支持事件摘要）；
3. **看一遍预览**：`npx ap preview --transport <每种方式>`，确认没有多余或缺失的段落；`--meta pure` 检查元指令时的提示词；
4. **检查默认配置**：新用户不做任何调整时，效果是否是你想要的。

如果用 Agent，可以直接说“按 ap-preset-testing 技能做一次发布前检查”。

## 版本号

`preset.yaml` 里的 `version` 用“主版本.次版本.修订号”的格式（如 `7.6.0`）：

- 修了错字、调了措辞：修订号 +1（`7.6.0` → `7.6.1`）；
- 加了新模组、新功能：次版本 +1（`7.6.1` → `7.7.0`）；
- 大改结构、改了 id：主版本 +1（`7.7.0` → `8.0.0`），并写好迁移。

如果用到了新版 AP 才有的功能，把 `minAdvancedPreset` 设为那个 AP 版本，旧版 AP 的用户安装时会被提示升级。

## 发布到 GitHub

模板自带的 GitHub Actions 会在每次推送时检查并构建预设。推荐的发布流程：

1. 修改 `preset.yaml` 里的 `version`；
2. 运行 `npm run build`，把更新后的 `dist/<id>.apreset.json` **一起提交**并推送（模板默认不忽略 `dist/`，花瓣也是这样做的）；
3. （可选）打一个以 `v` 开头的标签并推送，例如 `v1.2.0`，Actions 会自动创建 GitHub Release 并附上预设文件，方便用户下载。

用户的安装方式：

- **链接导入**：AP 面板 → 预设 → 导入**链接**，填入仓库中预设文件的地址，例如 `https://github.com/<用户名>/<仓库名>/blob/main/dist/<id>.apreset.json`（AP 会自动换成 raw 地址）。这个地址始终指向最新提交的版本；
- **从来源更新**：通过链接安装的预设，以后可以在“预设”页一键“从来源更新”；
- **文件导入**：下载 `.apreset.json`（比如从 Release 页面）后导入文件。

> Release 附件的下载地址不能直接用于“链接导入”：浏览器会因为跨域限制拒绝读取。分享链接请用仓库里的文件地址。

更新预设时，用户的配置修改、我的模组、记忆都会保留。

## 改名与迁移

用户的设置是按 id 记住的：模组开关记在模组 id 下，参数值记在参数 id 下，“我的模组”记住的是插入点 id 和变量名。发布后改了这些 id，用户的设置就会“对不上”。

真的需要改名时，在 `preset.yaml` 里写一条**迁移**，告诉 AP 从哪个旧版本升级上来时，哪些旧名字对应哪些新名字：

```yaml
migrations:
  - from: "<8.0.0"            # 从 8.0.0 之前的版本升级时
    rename:
      modules: { style-old: style-new }
      params: { wordCount: length }
      insertionPoints: { before-workflow: before-task }
      vars: { questions: mandatoryQuestions }
```

能不改就不改；新功能尽量用新 id，旧 id 保持原样。

## 常见问题排查

| 现象 | 可能的原因 | 怎么查 |
| --- | --- | --- |
| 某个模组没生效 | 开关没开；条件不满足；单选集合里选了别的 | 调试页“最近组装”看生效的模组列表；`npx ap preview --enable <id>` |
| 一段话出现两次 | 两个条目条件重叠（比如两种传输方式的版本都出现了） | 预览对应的传输方式 |
| 正文里混进了思考内容（对话式） | 模型没有输出正文标记或角色前缀 | 调试页“请求”看原始输出，加强写作阶段的格式说明 |
| 工具模式下模型不调用工具 | 模型能力不足或说明不清 | 试试示范轮次、强制工具调用；调整工具说明 |
| 卡片没出现 | 结构所在的模组没生效；模型没按格式输出 | 预览看格式说明是否出现；看原始输出 |
| 构建失败 | 文件格式错误 | `npm run check` 的报错会指出文件和行号 |
