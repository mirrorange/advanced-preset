# 1. 预设是什么，AP 又做了什么

## 一次请求里有什么

你在 SillyTavern（下文简称 ST）里点“发送”时，ST 会把很多东西拼成一份发给模型的**请求**。用 Chat Completion 接口时，请求是一串“消息”，每条消息有一个**角色**：

- **system（系统）**：给模型的说明，比如“你是一位小说家……”；
- **user（用户）**：你说的话；
- **assistant（助手）**：模型之前说的话。

一份典型的请求大致是这样排列的：

```
[system]    写作要求、文风、注意事项……         ← 预设写的
[system]    角色卡、世界书、用户人设……           ← ST 根据你的角色卡填入
[user]      第 1 轮：你说的话                    ┐
[assistant] 第 1 轮：模型的回复                  │ 聊天记录
……                                               │
[user]      最新一轮：你刚刚输入的话             ┘
[system]    最后的提醒：现在开始写……             ← 预设写的
```

**预设**就是其中“预设写的”那几部分，再加上温度、最大长度等采样参数。预设决定了模型以什么身份、按什么要求、用什么格式来写。

## 传统预设的难处

ST 自带的 Chat Completion 预设是一列提示词条目，每条可以开或关。写得复杂之后，常会遇到这些问题：

- **组合爆炸**：想同时支持“续写 / 扩写”“几种文风”“开不开 NSFW”，就得写很多版本，或者让用户自己记住哪些条目要一起开、哪些不能一起开；
- **不同模型要不同写法**：有的模型适合“预填充”（替模型写好回复的开头），有的模型更擅长按 JSON 格式或工具调用输出，同一份提示词很难兼顾；
- **思维链和正文混在一起**：让模型“先思考再写作”，思考内容就会出现在聊天记录里，占用 Token，还要靠正则清理；
- **附加功能靠外挂**：选项、状态栏、记忆、总结……往往要靠额外的正则、脚本或扩展拼起来。

## AP 做了什么

AP 把“预设”从一列条目变成一个**小型项目**：

| 你写的 | AP 帮你做的 |
| --- | --- |
| 一个个**提示词模组**（每个功能一个 Markdown 文件） | 根据用户的开关、单选、参数，挑出该生效的模组，按顺序放进对应位置 |
| 模组里的**条件**（“只在预填充模式下出现”“只在用户设置了语言时出现”） | 每次生成时自动判断，用户什么都不用管 |
| **工作流**：模型每轮要经过哪些步骤（提问、规划、写作、自检……） | 让模型按步骤输出，实时显示每一步；只把正文当作故事放进聊天记录 |
| 每段提示词的**两种写法**：对话式 / 指令式 | 根据所选的**传输方式**自动选择写法，并生成 JSON Schema、工具定义等技术细节 |
| 想用的**内置功能**：选项、记忆、总结、代写、事件摘要…… | 解析模型输出，把它们显示成卡片、存进记忆、用于节省 Token |
| 几套**推荐配置**（“Gemini 用这套”“DeepSeek 用那套”） | 用户一键切换；用户的修改单独保存，预设更新后依然保留 |

换句话说：**你专心写提示词、设计功能，技术活交给 AP。**

## 预设在用户那里长什么样

安装好 AP 和你的预设后，用户会在 ST 的 Chat Completion 预设下拉里看到 `AP · <你的预设名>`。选中它，AP 就接管了这个预设的生成。预设下拉下方会出现「当前预设使用 Advanced Preset」横幅，点击「打开面板」进入 AP 面板，里面有六页：

| 页面 | 用户在这里做什么 | 对应你设计的东西 |
| --- | --- | --- |
| 预设 | 安装、更新、切换预设 | 预设名称、版本、介绍 |
| 配置 | 选推荐配置、传输方式、工作流、采样参数 | [推荐配置](11-configs-and-extension.md)、[工作流](08-workflows.md) |
| 模组 | 开关模组、在单选组里挑一个；管理“我的模组” | [模组与分组](05-switches-and-params.md)、[插入点](11-configs-and-extension.md#插入点让用户加入自己的提示词) |
| 写作 | 填参数（语言、长度……）、改角色名称与前缀、节省 Token | [参数](05-switches-and-params.md#参数写作页上的输入框) |
| 记忆 | 查看、编辑聊天记忆、全局记忆与剧情总结 | [内置功能](09-built-in-features.md) |
| 调试 | 连接开发服务器、查看最近一次组装和请求 | [实时预览](03-setup-and-live-preview.md) |

## 一个 AP 预设由哪些文件组成

```
my-preset/
├─ preset.yaml          预设的“总设定”：名称、角色、区域、分组、参数、功能、推荐配置……
├─ modules/             提示词模组，一个文件一个模组，可以按文件夹分类
│  ├─ core/core.md
│  └─ guidelines/show-dont-tell.md
├─ workflows/           工作流，一个文件一个
│  ├─ linear.md
│  └─ task.md
├─ locales/zh-cn.yaml   面板上的中文名称（可选）
└─ package.json         开发工具的配置（一般不用动）
```

写好之后运行一次“构建”，这些文件会被合成一个 `dist/<预设 id>.apreset.json`——这就是发给用户安装的预设文件。

`.md` 文件主要是普通的 Markdown 文本，开头有一小段用 `---` 包起来的设定（叫 frontmatter）；`.yaml` 文件是“名字: 值”形式的设定。即使你从没写过它们也不用担心：照着模板改，或者让 Agent 来写，都很容易。
