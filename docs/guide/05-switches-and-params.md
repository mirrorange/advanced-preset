# 5. 开关、分组、单选与参数：把选择权交给用户

好的预设既要“开箱即用”，又要让用户能按口味调整。AP 提供四种调节手段：

| 手段 | 面板上的样子 | 适合 | 花瓣的例子 |
| --- | --- | --- | --- |
| 始终生效的模组 | 不显示 | 预设的骨架 | 核心模组 `core`、上下文 `context` |
| 开关 | 一个开关 | 可有可无的规则或功能 | 节奏控制、事件摘要、选项 |
| 单选 | 一组选项，只能选一个 | 互相冲突的方案 | 续写 / 扩写；五种主文风 |
| 参数 | 输入框、下拉框 | 需要填一个值的设定 | 回复语言、字数 |

## 始终生效与开关

模组默认是**用户可开关**的。把模组设为 `toggle: always`，它就始终生效、不在面板上显示——适合身份、核心规则、上下文这类“没有就不成立”的内容。

开关的**默认状态**写在预设的默认配置里（`preset.yaml` 的 `configurationDefaults.modules`），例如花瓣默认打开“事件摘要”“选项”，默认关闭“NSFW 协议”。推荐配置还可以改变默认状态（比如 Gemini 配置打开“跳过思考”）。用户自己的选择优先于这两者。

> “始终生效”只是不让用户关掉；模组仍然可以带[条件](06-conditions.md)。比如花瓣的“记忆系统”是始终生效的，但只在用户使用元指令时才出现。

## 分组

`group` 决定模组显示在“模组”页的哪个分组下。分组在 `preset.yaml` 的 `groups` 里声明名称、说明和顺序。花瓣的分组：

```
角色 → 模式 → 写作指南（其中有“叙事控制”单选）→ 文风（其中有“主文风”单选）→ 功能
```

没有分组的可开关模组会显示在“其他”下面，`ap check` 会提醒你给它们分组。

## 单选

有些模组不能同时生效：既“续写”又“扩写”会让模型无所适从。把它们放进同一个**单选集合**（在每个模组里写相同的 `exclusive`），AP 保证集合里同时只有一个生效。

单选集合也要在 `groups` 里声明一个同名的分组，用来给集合起名字，并决定**能不能一个都不选**：

- **必须选一个**（默认）：比如花瓣的“模式”（续写 / 扩写）。用户没选时，用标记了默认的那个，或者排在最前面的那个；
- **可以都不选**（`allowNone`）：比如花瓣的“主文风”。面板上会多一个开关，打开后才出现选项。

参考花瓣的文风设计：五种主文风（Kardia、Aisthesis、Antheia、Kryos、Melos）组成单选集合 `main-style`；Eros（NSFW 场景文风）**不在**集合里，是一个普通开关，可以叠加在任何主文风之上。它们都在“文风”分组下显示。

```yaml
# 文风模组的 frontmatter
group: style            # 显示在“文风”分组
exclusive: main-style   # 属于“主文风”单选
```

```yaml
# preset.yaml
groups:
  style: { label: Writing Style, order: 40 }
  main-style: { label: Main style, allowNone: true }
```

设计单选时问自己：**这些选项会互相矛盾吗？** 会，就做成单选；不会，做成几个开关让用户自由组合。

## 参数：写作页上的输入框

有些设定不是“开 / 关”，而是一个值：用什么语言写、写多长。这类设定做成**参数**，显示在“写作”页上。参数有三种：

| 类型 | 面板上 | 例子 |
| --- | --- | --- |
| 文本 | 输入框（可附带几个常用选项） | 回复语言：简体中文 / English / 日本語…… |
| 数字 | 数字框（可设单位、最小值、最大值、常用值） | 回复长度：400 / 600 / 800 字 |
| 选择 | 下拉框 | 长度策略：大约 / 至少 / 至多 |

在提示词里用 `{{ap::param::参数名}}` 读出参数的值：

```markdown
- Write the story content in {{ap::param::language}}.
```

参数有几个很贴心的设计，花瓣都用上了：

- **默认值**：语言参数留空时，`{{ap::param::language}}` 会变成“the language used in the story so far”（沿用故事已有的语言），而不是空白；
- **后备参数**：“对话语言”“工作流语言”留空时，自动使用“回复语言”的值；
- **选择项的文字**：“长度策略”在面板上显示“At least”，写进提示词时是“at least”；也可以让面板显示中文、提示词保持英文；
- **没设置就不出现**：配合[条件](06-conditions.md)，只在用户填写了长度时才加入“长度”规则——用户不填，就不打扰模型。

参数也要放进分组（分组设为显示在“写作”页），花瓣有“语言”“长度”两个分组。

## 设计建议

- **默认值要好用**：大部分用户不会调整设置。默认配置应该在你主要支持的模型上直接写出好效果；
- **开关不是越多越好**：每多一个开关，用户就多一分困惑。只把“确实有人想关掉”的东西做成开关；
- **名字和说明写给用户看**：说明这个开关打开后有什么变化、什么时候该打开。中文界面可以在[界面翻译](11-configs-and-extension.md#界面翻译)里单独写；
- **id 要稳定**：模组、参数、分组的 id 是用户设置的“钥匙”，发布后改名会让用户的设置失效。实在要改，用[迁移](12-test-and-release.md#改名与迁移)告诉 AP 新旧名字的对应关系。
